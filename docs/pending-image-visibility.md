# Image visibility after an acknowledged chat send

An acknowledged image-only chat request previously had no temporary user bubble. A request containing both a caption and images kept only the caption until canonical history arrived. The composer cleared its attachments after acknowledgement, leaving a visible gap even though the outgoing request included the images. The same conditions are present in the previously installed Lotus source `58920d5b` and the local `b32d8ccf` base.

`useChat` now captures the submitted image metadata and keeps it with the acknowledged, session-scoped pending message. `ChatPane` passes that state to `MessageList`, which shares its existing image renderer between pending and canonical messages. Pending thumbnails retain the existing zoom interaction. Arrival of the matching canonical user message retires text and thumbnails together, without a duplicate frame. The wire request, history schema and model policy are unchanged.

The synthetic regression covers image-only and captioned sends, outgoing metadata, navigation away and back, exact message-ID hydration, pending preview interaction, and canonical `bamboo-attachment://` history mapping. Four new regressions fail on the base and pass after the fix. The three affected unit/component files pass 251 tests; type-check, lint and architecture checks pass. This 251-test selection is specific to the image change, not the older Supervisor scope test batch. A synthetic desktop/phone browser fixture is included but has not yet run: the single new asset build is deferred while the scope contract is being finalized. No browser or actual user-session acceptance is claimed here.

The user's non-vision model symptom is a separate backend observation. Current Bamboo context preparation rejects an `ImageUrl` when the selected model reports no vision support, before the model request. That path does not automatically call `view_image`; the independent tool-result resolver needs a configured vision-capable helper. These are source findings, not a reading of the user's private conversation or configuration. This UI fix does not enable vision, select a helper model or start a paid model/tool call. Actual provider/model capability and the intended fallback policy remain with the backend owner (related Bamboo issues #2014 and #2017).

This isolated change is local only. It does not modify the frozen Supervisor scope artifacts, backend, running fixture, credentials, permissions, release or package publication.
