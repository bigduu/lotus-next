# Run diagnostics

The generation/submission error alert has an optional **View diagnostics** action. It loads a local preview only when requested. The user reviews the exact JSON and explicitly downloads it; opening, cancelling or downloading does not upload, invoke a model/tool, retry a generation or change session permissions. The original technical error string and existing Retry behavior remain intact.

The current Bamboo candidate contract is source 16821971892b96d1e43715586c984aa1b586f34d. Its public terminal string may append one exact lowercase UUID-v4 marker, `Diagnostic ID: <UUID>.`. Lotus extracts only that bounded terminal marker, for observation. Malformed, ambiguous, nonterminal or absent markers do not become diagnostic IDs. Prose such as “1 request(s)” is not parsed into a retry policy.

Structured failure stage, retry stop reason, attempts/limit and authoritative run association are **not currently supplied through public error events or canonical last-run reads**. This UI shows them as not provided. It does not assume the proposed diagnostic properties exist, call an invented endpoint, or invoke bamboo_diagnostics to collect them. Provider-layer run_id=null must not be presented as an Engine run ID.

The export is constructed from an explicit allowlist: schema version, collection time, bounded public Lotus version/revision/host kind, a canonical conversation identifier when recognized, a numeric client operation identifier, failure category and the strictly validated diagnostic ID. Collection time is not claimed to be the error occurrence time. No error prose, messages/reasoning, tool arguments/results/stdout, files, screenshots, settings, endpoints/query strings, headers, tokens, cookies or credentials are copied. Unknown and malformed values are omitted/null; arbitrary object dumps and regex-only redaction are not used. The preview contains linkable support identifiers, which the user can review before sharing the file.

A new session or failure identity closes a stale or still-loading preview. Its download action also verifies the exact open-preview identity at click time, so closing or reopening the same failure cannot reactivate an old handler. Correlation IDs never authorize retry, session control or convergence. This is a plain-browser feature; Bodhi needs no task-business or native-only pathway.

Local tests cover strict legacy marker parsing, allowlist/privacy boundaries, local download mechanics, lazy cancellation and cross-session/new-failure isolation. These framework checks do not establish that the backend candidate is compiled, deployed, or exercised through a real diagnostic transport. The missing server integration is a bounded public diagnostic projection attached to the exact error event and canonical matching last-run error; its wire schema and association remain with the existing backend owner.
